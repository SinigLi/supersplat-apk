## 0.1 v49c：返回按钮失效（2026-11-06 晚）

| 现象 | 根因 | 修复 |

> 探针新增 4 条断言（打开可见 / 返回后隐藏 / 列表可点 / 二次往返），并把「运行时异常」计入失败条件，顺带抓出并修掉了 `applySafeArea` 延迟重读里的 `TypeError`（插件存在性只在入口查一次，定时器回调空手敲门）。

> 教训存档：`0.82` 半透明直接进笔画是「看起来像有特性、其实是 bug」的典型。任何「层内叠加 + 层统一半透明」的场景，都该把透明度放在层上而不是每个 primitive 上。

## 1. 背景

现有三种工程模式（3D 模型 / 视频 / 音频）。新增第四种：**图片**。

导入一张图片 → 缩放平移查看 → 在画面上画遮罩（涂抹 / 多边形）→ 分享时按遮罩把对应区域 alpha 置 0，导出 PNG。

用途：抠图。画哪里挖哪里。

## 2. 已锁定决策（原型验证 + 老板确认）

| # | 决策项 | 取值 |
|---|---|---|
| 1 | 遮罩语义 | **画 = 挖除**（导出时该区域 alpha=0） |
| 2 | 橡皮作用对象 | **改蒙版**，不改图片像素；笔画顺序携带语义（先画后擦=补回，先擦后画=仍挖） |
| 3 | 笔画宽度 | 画笔 / 橡皮**共用一个值**（抠图修边需要同宽；jspaint 分离式不采用） |
| 4 | 多边形结束 | ~~双击 / 再点按钮~~ → **松手自动闭合**（v49b 修订，见 §0） |
| 5 | 缩放/平移 | 单指平移、双指缩放，**固定手感**，不做游戏/建模双模式（图片无 3D 尺度问题） |
| 6 | 图片数量 | **单张**（多张列表不做，见 §8） |
| 7 | 反选 | **保留**（⇄ 按钮，画背景比画主体省事） |
| 8 | 存储形态 | **笔画路径数组**，不存位图（撤销=弹栈；工程文件小） |
| 9 | 框架 | **不引入 fabric.js / Konva**，手写 canvas（理由见 §9） |
| 10 | 撤销粒度 | 一笔 = 一个撤销单元（通用约定） |

## 5. 数据结构

**meta（localStorage `img-<名>-meta`，与 av-store 同风格）**

```json
{
  "version": 1,
  "name": "示例",
  "mode": "image",
  "imageFile": "files/a1b2c3....png",
  "imageW": 1200, "imageH": 900,
  "invert": false
}
```

**笔画（project.json 内嵌或独立文件，随工程 zip 走）**

```json
{
  "schema": "moyutai.imgmask.v1",
  "strokes": [
    { "type": "brush",   "size": 24, "points": [[x,y], ...] },
    { "type": "polygon", "size": 24, "points": [[x,y], ...] },
    { "type": "erase",   "size": 24, "points": [[x,y], ...] }
  ]
}
```

- 坐标一律**原图像素**，与视图变换无关（原型已验证：变换后笔画不错位）
- `invert` 反选只存标志位，渲染/导出时对蒙版整体求反

## 6. 渲染与导出（原型的核心机制，直接移植）

**单一渲染器 `drawMaskInto(ctx, {alpha, rgb, showAids})`**——屏幕预览与导出共用，杜绝两套顺序语义：

```
brush / polygon → source-over      （往蒙版上盖 = 要挖的区域）
erase           → destination-out  （从蒙版抹掉 = 补回）
```

**透明度必须放在层上，不放在笔画上**（v49b 修正）：

| 位置 | 取值 | 原因 |
|---|---|---|
| 预览蒙版层 `.img-mask` | CSS `opacity:.82` | 整层统一降透明，重叠多少遍都不加深 |
| 笔画本身（`drawMaskInto` 的 `alpha`） | `1` | 半透明进笔画会随重叠累积（`1-(1-a)^N`） |
| 导出离屏 canvas（`alpha`） | `1` | 导的是硬遮罩，alpha 只作二值掩码用 |

`redrawMask()` 因此调用 `drawMaskInto(mctx, {alpha: 1, ...})`，不要改回 `0.82`。

**导出**：蒙版画到离屏 canvas（alpha=1）→ 原图 `destination-out` 蒙版 → `toDataURL('image/png')` → SaveImage 分享。

**双层 canvas**：底层图片只在视图变换时重绘，上层蒙版只在笔画变化时重绘。大图（4000×3000）绘制不卡的关键。

### 8.2 复用性架构（为视频工程弹窗编辑铺路）

`www/img-ui.js`（870 行全页壳）拆两层：

- **`img-core.js`**（纯编辑器）：状态机 + 双层 canvas + 图层 + 撤销 + 导出合成。不碰工程系统/localStorage/顶栏。对外 `ImgEditor.mount(container, opts)` → `{ export(opts), getLayers(), setImage(bytes), undo(), redo(), destroy()` }`
- **`img-page.js`**（全页壳）：工程读写、meta/strokes 落盘、安全区、返回。内嵌一个容器调 `ImgEditor.mount`
- 视频工程以后弹窗编辑 = 弹窗壳（`av-ui` 侧）+ 同一个 `ImgEditor.mount`，`export()` 拿结果关窗

迁移必须不破坏现有探针：`window.__img` 的导出面（state/_setTool/_undo/_redo/_exportCanvas）保持不变或适配。

## 8. 明确不做（本轮）

- 多张图片列表（同工程多图切换）
- 多边形顶点拖拽编辑
- 画笔/橡皮宽度分离
- 选区、羽化、笔刷形状、透明度调节
- 撤销跨会话合并（按笔画原样存）
- 导出时把挖除区填白（老板 2026-11-06 提问后确认按原需求保持 alpha=0，需要再说）

> 「透明度调节」不做，但**预览层**的 82% 是固定样式，不是可调参数——见 §6。
