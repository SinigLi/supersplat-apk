## 0. 背景与目标

- 老板手机收到的大型文件（游戏主美分段压缩发送链路：>30MB 自动 7z 分卷）目前无解压手段，需要摸鱼台内置解压能力。
- 音视频助手已有一套自动切分流水线（scene_split / audio_split），但部分段落需要**人工重新切分/合并**。摸鱼台不实际切割音视频，只负责：**播放浏览 → 打标记 → 导出 JSON → 交回音视频助手执行真实拆分/合并**。
- 摸鱼台从单一 3D 导演台升级为三模式工作台：**3D 模型工程（现有，默认）/ 视频工程 / 音频工程**。

## 3. 技术方案

### 3.1 解压中心（R1–R3）

- **入口**：工程列表页顶栏「新建」左侧新增「解压」按钮（dock 顶层菜单，三模式通用）。
- **选文件**：Android SAF 文件选择器（`application/octet-stream` 不设 MIME 白名单——v15 教训，accept 属性会屏蔽 .7z/.001）。
- **格式与分卷策略（P0 必须技术预研）**：
  - zip / 7z：主链路。**7z 分卷不依赖解压库的分卷支持**——`.7z.001…NNN` 按序字节拼接成完整 .7z 再解压（7z 分卷是设计上可拼接的；zip 分卷 `.zip.001` 同理拼接后可解）。
  - 解压库候选：**7z-wasm**（p7zip 编译 wasm，单文件可用，含 7z/zip/gz 等）；zip 也可走现有 fflate（已在工程系统里用）。
  - rar：需要专有 unrar（许可证/体积问题），**默认不做**，见 Q1。
- **目标目录规则**：
  1. 优先：压缩包所在目录（SAF tree URI，取 `takePersistableUriPermission` 持久授权）下建 `同名文件夹/`；已存在则 `同名_exp/`、`同名_exp2/`……
  2. 兜底：SAF 对源目录创建受限时，落应用可见目录（`Pictures/摸鱼台/extracted/<名>/` 或 Download），完成后弹提示告知路径。
- **大文件**：流式写盘（v29 已有分块复制/增量 SHA-1 基建），解压过程显示进度，不整包驻留内存。
- **输出**：解压完成 → 提示解压路径与文件数；失败给出具体卷缺失/校验错误。

### 3.2 三模式工程（R4–R5）【D2 已定：文件列表不依赖 CSV】

- **新建页**：现有「新建」弹出三选一卡片（3D 模型 / 视频 / 音频），默认选中 3D。模式存进工程元数据 `mode: 'model'|'video'|'audio'`（svproj v2 zip 兼容：新模式工程同样自包含，但**媒体文件不进包**，见下）。
- **工程存储差异**：音视频工程只存「引用 + 标记」：
  - `folderUri`（SAF 目录授权，持久化）+ 文件清单快照（文件名/序号/时长/大小）
  - `marks.json`（标记）
  - 不复制媒体进工程包——单个源视频 300MB，进包不现实（v29 181MB 教训）。
- **文件列表数据源（D2）**：读用户选的文件夹，按文件名排序；解析文件名尾部标号（如 `shot003`/`seg012`）作为段号；无标号的按列表顺序自动分配序号并在 UI 标注「自动」。
- **音视频工作台布局**（横屏）：
  - 左 30%：文件列表（按文件名排序），顶部「加载文件夹」（SAF 目录选择）+ 收起箭头（收起后全宽播放区，边缘留把手）。
  - 右 70%：视频=video 元素；音频=Canvas 时频图 + 波形概览。
  - 底部播放条：当前时间（左上角，两位小数秒）/总时长，可拖动可点选；视频左右各有「上一条/下一条」。
  - 播放条上方工具行：「✂ 分割点」「⤴ 与前一段合并」+ 步进组（◀ 步进值 ▶，步进框可编辑，视频 1 帧 / 音频 0.05s 默认）。
  - 标记在时间轴上叠加显示（可点击跳转、可删除）——老板未提，**建议加**，见 Q7。

### 3.3 视频工作台细节（R6/R8/R9）

- 播放：Android WebView 原生 video（h264/aac mp4 全支持；webm 视 codec）。
- **帧步进**：`video.pause(); video.currentTime ± (1/fps)`。fps 获取：`requestVideoFrameCallback` 播放 1 秒采样估算 + 手动修正框（Q4）。
- 当前帧显示：`帧 = floor(t × fps) + 1`，旁边显示秒（两位小数）。
- 「上一条/下一条」= 文件列表相邻项切换，自动保留同一播放位置策略（从 0 开始）。

### 3.4 音频工作台细节（R7）【D4 已定：单轨 vocals 类】

- 音频列表 = 用户选的文件夹下的音频文件按顺序读（不预设 stems 结构，用户选 vocals 文件夹就读 vocals）；解码：WebAudio `decodeAudioData`（wav/mp3/flac/m4a 原生支持；大 wav 52MB 实测量级可行， decoded 后内存 ×4 需注意——**只解码当前播放的段**，不整目录预解码）。
- **时频图**：Canvas 逐帧绘制——STFT（FFT 变换，窗长 1024–2048、Hann 窗、50% 重叠）、幅度→dB→配色映射；配色与窗长向音视频助手对齐（Q6）。缩放：时间轴=播放缩放联动，频率轴对数/线性切换（建议默认线性）。
- 播放：`AudioBufferSourceNode` + 自绘播放头；播放条拖动=seek。
- 步进：`t ± 步进值`（默认 0.05s，可改），步进后重绘播放头与局部时频图。

### 3.5 标记系统与 JSON 导出（R10，格式草案 v0 待讨论）

标记数据模型（摸鱼台内部）：

```jsonc
{
  "marks": [
    { "id": "m1", "type": "split",       "seg": "shot003", "at": 12.34, "note": "" },
    { "type": "merge_prev", "seg": "shot007", "note": "和上一镜是一个动作" },
    { "type": "split", "seg": "seg012", "at": 105.07, "note": "这句话被切断" }
  ]
}
```

- `target` = 文件名（含尾部标号，如 `shot003.mp4`；无标号文件用自动分配序号 `auto-07`），`at` = 段内相对秒（两位小数）；`type`：`split`（此处再切一刀）/ `merge_prev`（本段并入前一段）。CSV 存在时可附带解析出的镜号增强信息，但**不是必需**（D2）。
- **导出 JSON 草案 v0**（发音视频助手的信封）：

```jsonc
{
  "schema": "moyutai.marks.v1",
  "mode": "video",                          // video | audio
  "source_dir": "让子弹飞这是你吗-名场面_split",
  "source_file": "让子弹飞这是你吗-名场面.mp4",
  "fps": 25.0,                               // 视频工程才有
  "based_on_csv": "分镜清单.csv@2026-10-18 10:37",  // 所依据清单的版本痕迹
  "marks": [
    { "action": "split", "target": "shot003", "at_seconds": 0.80, "at_frame": 20, "note": "" },
    { "action": "merge_prev", "target": "shot007", "note": "" }
  ]
}
```

- `at_frame` 优先（scene_man 切点本来就帧精确）；音频侧只给 `at_seconds`（audio_man --at 秒）。
- 音视频助手侧映射：`split target shot003 at_frame 20` → `scene_man split --shot 3 --at-frames 20`；`merge_prev shot007` → `merge --shots 6,7`；音频同理映射 audio_man。**一次导出含多条标记时按目标段号降序排列**（规避镜号平移问题——音视频助手文档明确要求降序执行）。
- 传输方式：先导出 JSON 文件（走现有「另存为/分享」链路），老板手动发 PC（Q8）。

### 3.6 与音视频助手的闭环

1. 主美/音视频助手把 split 目录（或原始媒体+清单）打包发飞书 → 手机。
2. 摸鱼台「解压」→ 得到 split 目录副本。
3. 新建视频/音频工程 → 加载该文件夹 → 播放 → 打标记。
4. 导出 JSON → 发回 PC → 音视频助手按标记执行 scene_man/audio_man → 新目录再发回手机复核。
